# CRM_REUSE_MATRIX — H2O / ICS CRM-1

Each classification was made against **current source** at the CRM baseline, not against historical
findings. Every entity receives exactly one of: `REUSE_AS_IS`, `REUSE_WITH_H2O_ADAPTER`,
`H2O_LOCAL_REQUIRED`, `SHARED_CHANGE_REQUIRED`, `DEFERRED`, `CONFLICT_BLOCKED`.

**Slug policy.** All H2O-local CRM collections use a `crm-` prefix, so none can collide with an
agency-core slug (`contacts`, `tasks`, `activities`, `companies`) if that layer is ever registered
alongside. This follows the accepted `product-media` precedent (2A.1B decision A1).

## Shared-change analysis

No H2O requirement needed a change to agency-core or syed-ai.

- **Agency-core contacts alias folding.** This is a real semantic disagreement with E0.1. It is
  resolved by H2O-local `crm-contacts`, not by altering the shared normaliser, which syed.ai
  depends on. It is recorded as an **observation** for the future generic Revenue Engine
  (`CRM_SHARED_CHANGE_REQUESTS.md` item O-1). It is not a request.
- **Audit `REDACT_VALUES` slug set.** This is resolved with an H2O adapter. It is recorded as
  observation O-2 (a generic `redactValues` collection flag would be the cleaner shared design).
