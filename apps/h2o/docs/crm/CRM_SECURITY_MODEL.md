## Known residual risks (reported, not patched)

1. **R1 — Payload Local API trust.** Any server code that calls the Local API with `overrideAccess` and a
   forged `context.crmServer` is trusted as intake. This is inherent to in-process code and is mitigated
   by the rule that only `src/crm/**` constructs that context. The rule is reviewable, not enforced by a
   test.
2. **R2 — Pre-existing baseline defect (outside CRM-1).**
   - The accepted migration `20260913_012440` has a generated DOWN that fails. Its
     `payload_locked_documents_rels_*_fk` constraints are dropped after `DROP TABLE … CASCADE`. This was
     observed while proving the CRM rollback.
   - The CRM-1 migration's DOWN was reordered to avoid the same defect. The baseline file was **not**
     edited.
   - Owner: Commander / Control Tower.
3. **R3 — Pre-existing stale `importMap.js`.** At baseline it was `{}`. Regenerating it for the CRM view
   also adds 14 Lexical entries and `CollectionCards`, which the admin already needed. The file is
   generated and is not hand-edited. This is recorded in `CONTROL_TOWER_REPORT.md`.
