How persistence works

Saved on this machine, in this browser

Projects live in IndexedDB: settings, every parsed export, crawl results and the history of every run. Closing the tab, restarting the browser and rebooting all leave it intact. Clearing site data removes it, and it does not follow you to another machine or another browser.

Use Export to write the whole project, data included, to one JSON file. That file is the backup and the way to move a project between machines or hand it to a colleague.

Whose links are actually different.

Load a Semrush backlinks export for your page and for each page outranking it, and this compares the profiles side by side: referring domains, follow against nofollow, text against image, the authority of the domains linking in, and the anchor mix. Your own key, for the writing only.

Paste a key from your own AI provider and it will explain a finding in plain English, read a draft against the queries it is meant to answer, or write the client summary. Everything it produces is marked generated and none of it can reach a score, a pillar or a saved run — the model is told so in its instructions, and the scoring engines have no way to read it. The key stays in this browser and is sent only to the provider you choose.

Write against your own evidence.

Paste or write a draft and it is scored by the same readiness engine that scores your crawled pages — not a separate one, so the editor and the audit can never disagree about the same page. Eligibility and internal links are left unscored: nothing links to a page that does not exist yet. This is an editorial checklist with numbers on it, not a gate, and nothing here leaves the browser.
