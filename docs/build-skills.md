# Build-time design skills

Skills are markdown instructions that shape how Claude Code writes components. They are **build-time only** (master prompt principle 4): they never run on a client server, never touch runtime AI, and never override the design contract. Precedence is fixed:

1. `design-contract.json` (declared values win over everything)
2. Block registry (approved components and their variants)
3. Quality gates (contrast, a11y, parity, residue, Lighthouse)
4. Skill advice

A skill may propose; the contract and the gates decide. Every skill is read in full before it is added, pinned to a commit, and listed here with why it is in and what we ignore. Adding or removing one is a decision-log entry (ADR-021).

Install location: `.claude/skills/<name>/`, produced by `pnpm skills:install` from **pinned npm packages** (`ui-ux-pro-max-cli`, `ux-ui-agent-skills`) plus the vendored Anthropic `frontend-design` SKILL.md (content-hashed). `MANIFEST.json` records versions, hashes, and what was excluded, and is the lockfile: `pnpm skills:install` exits 2 when any hash or version differs from it, until the diff has been read and the run repeated with `--accept-new-hash` (ADR-023). Renovate groups skill updates for human review because they are prompts. Nothing under `apps/` or `packages/` depends on a skill's presence.

**Excluded on inspection (C3):** UI/UX Pro Max's `scripts/{cip,icon,logo}` generators call the Gemini API — build-time skills make no provider calls. Its Tailwind/shadcn `ui-styling` and `design-system` skills are not installed.

## Operating rules

- A skill's output is reviewed like any other change: lint (`no-hex-in-components`), contrast gate, a11y e2e, parity, residue scan.
- Skills never receive client content, CRM data or secrets; they see code and the design contract.
- When a skill's advice conflicts with the contract, the conflict is recorded as a possible contract improvement (`source.kind: declared` if adopted), never applied silently.
- Preset library (Release 3): five to eight curated presets, each a contract with a distinct type pairing and geometry plus its taste-skill knob settings; `pnpm create-site` offers them as starting points. Quantity is capped deliberately.
