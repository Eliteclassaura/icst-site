# P5 — `tools/wordpress-import` specification

**Input:** a WordPress SQL dump (`.sql`/`.sql.gz`), the `wp-content/uploads/` tree, a sanitised `wp-config.php` *or* an explicit `--table-prefix`, and an approved `page-decisions` file. Never reads DB credentials; never connects to a live database.

**Parsing:** load the dump into a throwaway local MySQL/MariaDB container (`docker run --rm mariadb`) or parse `INSERT` statements directly for the handful of tables needed; either is acceptable, the container is simpler and handles serialized PHP in `wp_options`/`wp_postmeta` via a small PHP-unserialize port.

**Tables:** `wp_posts` (post_type page/post/product/product_variation/attachment/nav_menu_item, post_status publish/draft/private, post_name, post_parent, post_content, post_excerpt, post_date/modified, post_author), `wp_postmeta` (`_thumbnail_id`, `_wp_attached_file`, `_wp_attachment_image_alt`, Yoast `_yoast_wpseo_title/metadesc/canonical/meta-robots-noindex/schema/focuskw/opengraph-*`, RankMath `rank_math_title/description/canonical_url/robots/focus_keyword`, WooCommerce `_sku/_price/_product_attributes`, Elementor `_elementor_data`), `wp_terms` + `wp_term_taxonomy` + `wp_term_relationships` (category, post_tag, product_cat, product_tag, custom), `wp_options` (`permalink_structure`, `siteurl`, `home`, `page_on_front`, `page_for_posts`, SEO-plugin settings blobs, `blogdescription`), `wp_users` (ID, display_name only — never user_pass/user_email), `wp_redirection_items`/`wp_redirection_groups` if the Redirection plugin was installed, `wp_yoast_indexable` if present.

**URL reconstruction:** apply `permalink_structure` per post type; produce `source_url` for every public object including attachment pages, taxonomy archives, author archives, paginated archives, and `?p=` variants; reconcile against the discovery-pack `URL_MASTER.csv` and against the live sitemap; anything in the crawl but not in the DB (or vice versa) goes to `DATA_GAPS.md`.

**Content → blocks:** Gutenberg comments (`<!-- wp:… -->`) map directly to registry blocks where a match exists (heading/paragraph/list/image/table/quote → `richText`, `dataTable`, `faq` via Yoast/RankMath FAQ blocks, `steps` via HowTo blocks); Classic editor HTML and Elementor JSON go through a `Section` AST like `tools/legacy-extract/dom.ts` with prose fallback so no text is lost; shortcodes are expanded where known, otherwise preserved as text with a `DATA_GAPS` entry. Images: copy from `uploads/` to `apps/<client>/content/media/`, carry `alt`, set `rights: 'unknown'` unless the decisions file says otherwise (publish gate R34 then blocks until resolved).

**Decisions applied:** join by canonicalised `source_url`. PROTECT/IMPROVE/REWRITE/REPOSITION/CONSOLIDATE-target → page emitted (REWRITE/REPOSITION as draft with `verification.status: unverified`); CONSOLIDATE-source and REDIRECT → no page, `redirects[]` row; NOINDEX → page with `seo.noindex: true` + reason; PRUNE → no page, `redirects[]` 410 row, `migration.finalMigrationAction: PRUNE` recorded in a sidecar `pruned.json` (never in Payload); REVIEW → page as draft. `decisions_status: draft` downgrades PRUNE/REDIRECT/NOINDEX to REVIEW. `seo_lock` → `seo.lock` and `migration.seoLocked`.

**SEO fields:** title/description from the SEO plugin meta, falling back to the discovery-pack crawl record (`claude-pages/*.json`) which reflects what was actually rendered; canonical stored `null` for self-canonical (matches current seed behaviour); `schemaExtra` carries any plugin-emitted JSON-LD the crawl captured that the block-derived graph cannot yet reproduce (ADR-025 "carry, then generate").

**Output:** `apps/<client>/content/<client>.blueprint.json` v2 (validated), `apps/<client>/content/media/*`, `handoff/import/<run_id>/{pruned.json, unmapped-shortcodes.json, url-reconciliation.csv}`. Deterministic: same inputs → byte-identical blueprint (sorted keys, stable ordering by `source_url`).

**Tests:** golden fixture (`fixtures/wp-small.sql.gz`: 10 posts, 3 pages, 2 products, Yoast meta, one menu, one Redirection rule) + fixture decisions → expected blueprint; negative: draft decisions produce no PRUNE; `wp_users.user_pass` never appears in any output (grep in test).
