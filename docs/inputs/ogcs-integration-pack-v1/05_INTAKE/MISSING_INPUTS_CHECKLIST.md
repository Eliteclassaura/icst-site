## A. Hostinger — OLD H2O site → `02_UPLOAD_YOUR_SITE_EXPORTS/OLD_H2O_WORDPRESS/`

### A1. Files backup (preferred route: hPanel Backups)

1. Log in to hPanel → **Websites**.
2. Click **Dashboard** on the OLD H2O site (double-check the domain shown at the top).
3. Left menu → **Backups** (may read **Daily Backups** on Agency plans).
4. Under **Files backups** choose **Select** and pick the newest date that clearly represents the OLD site.
5. Click **Prepare to download**, wait, then **Download**. You get a `.tar.gz` or `.zip`.
6. Rename it `h2o-old-files-YYYY-MM-DD.tar.gz` (use the backup date) and move it into the OLD folder.

*Alternative (exact current files):* Dashboard → **File Manager** → open the domain folder → right-click `public_html` → **Archive** → download. Only archive that one site's folder; don't include other domains on the plan.

### A2. Database backup

1. Same Dashboard → **Backups** → **Database backups** → **Select**.
2. **Pick the database that belongs to the OLD site.** If several databases are listed and you're not sure which, see A4.
3. Prepare → Download → rename `h2o-old-db-YYYY-MM-DD.sql.gz` → move into the OLD folder.

*Alternative:* Dashboard → **Databases** → **phpMyAdmin** → **Enter phpMyAdmin** for the right DB → **Export** tab → Method *Quick*, Format *SQL* → **Export**.

### A3. Other OLD-site items

- **Redirects / .htaccess:** already inside the files archive (`public_html/.htaccess`). Also, in hPanel Dashboard → **Redirects**, screenshot or copy any rules defined at the hosting level (these are *not* in the archive).
- **robots.txt and sitemaps:** inside the archive if physical; if generated by an SEO plugin (Yoast/RankMath), they'll be in the DB. Also save the live versions: open `https://<old-domain>/robots.txt` and `https://<old-domain>/sitemap_index.xml` (or `/sitemap.xml`, `/wp-sitemap.xml`) in a browser and **File → Save Page As** into the OLD folder as `robots-live.txt`, `sitemap-live.xml`.
- **Uploads/media:** inside the files archive under `wp-content/uploads/`. No separate step.

### A4. Confirm the correct database and sanitise `wp-config.php`

1. Extract the files archive locally (don't upload the extracted copy anywhere yet).
2. Open `public_html/wp-config.php` in a text editor.
3. Note the value of `DB_NAME` — that is the database you need in A2. Note `$table_prefix` too.
4. Make a copy called `wp-config.sanitized.php`. In the copy, replace the values of `DB_PASSWORD`, `DB_USER`, `DB_HOST`, `AUTH_KEY`, `SECURE_AUTH_KEY`, `LOGGED_IN_KEY`, `NONCE_KEY`, `AUTH_SALT`, `SECURE_AUTH_SALT`, `LOGGED_IN_SALT`, `NONCE_SALT` and any third-party API key with `REDACTED`. Keep `DB_NAME`, `$table_prefix`, `WP_DEBUG`, `WP_HOME`/`WP_SITEURL`, multisite constants, etc.
5. Put `wp-config.sanitized.php` in the OLD folder. Leave the original archive as is — I will not read the un-sanitised file's secret lines, and I'll flag it on receipt.

## C. Google Search Console → `03_UPLOAD_SEO_DATA/GSC/`

### C1. Preferred: Search Evidence Suite connector (up to 100k rows per table)

The suite's built-in GSC connector pulls far more rows than the UI export. Use it if you can:

1. Open your Search Evidence Suite installation (HTTPS). Create or open the **H2O** project (domain `h2ocooling.com`).
2. Follow `CONNECT-SEARCH-CONSOLE.txt` from the suite: you need a Google Cloud OAuth **client ID** (not a secret) added to the project settings. The token stays in your browser.
3. Connect, then import **Queries, Pages, Page+Query, Dates, Countries, Devices, Search appearance**, with the longest window offered, **with previous period and year-ago comparison** enabled.
4. If the property shows Generative AI performance, import that too.
5. Then do **section F** (export the project) — the GSC rows travel inside the `.seoproject.json`.
6. Still do C2 for at least Queries and Pages as an independent cross-check, and for indexing/sitemap reports the connector doesn't cover.

### C2. Manual export from the Search Console UI

1. Open [search.google.com/search-console](https://search.google.com/search-console) → select the H2O property. **Note whether it is a Domain property (`h2ocooling.com`) or URL-prefix property (`https://www.h2ocooling.com/`)** — write this in a `GSC_NOTES.txt`.
2. **Performance → Search results**.
3. Date filter → **Last 16 months** (maximum). Enable **Compare** → *Last 3 months vs previous period* as a second pass later.
4. Top-right **Export** → **Download CSV** (a zip of one CSV per tab). Do this for the 16-month view. Rename the zip `gsc-performance-16m-YYYY-MM-DD.zip`.
5. Change the date to **Last 3 months, compared with previous period** → Export again → `gsc-performance-3m-compare-YYYY-MM-DD.zip`.
6. Change to **Last 3 months compared with same period last year** → Export → `gsc-performance-3m-yoy-YYYY-MM-DD.zip`.
7. The export zip contains Queries, Pages, Countries, Devices, Search appearance, Dates tabs — so M5–M7 come out together.
8. **Indexing → Pages**: Export → `gsc-indexing-pages-YYYY-MM-DD.zip`. Also screenshot the summary chart.
9. **Indexing → Sitemaps**: screenshot the list (submitted URLs, discovered, status) → `gsc-sitemaps-YYYY-MM-DD.png`.
10. **Settings → Crawl stats**: Open report → screenshot the totals and the "By response" / "By file type" tables → `gsc-crawl-stats-*.png`.
11. **Security & Manual actions**: screenshot both (expected: "No issues detected").
12. If **Performance → Generative AI** (or similarly named) exists: export → `gsc-genai-YYYY-MM-DD.zip`.

**Caveat:** UI exports are capped (typically 1,000 rows per table). For a site with a large product catalogue this is not the whole picture. Prefer C1, or — if you want an API pull — tell me and I'll prepare a script you run locally with your own OAuth client; I don't need your credentials.

## D. SEMrush → `03_UPLOAD_SEO_DATA/SEMRUSH/`

Log the **database/country** (e.g. US, UK, Worldwide), **date** and **domain form** (`h2ocooling.com` root domain) in `SEMRUSH_NOTES.txt`. Use **Export → CSV** (or XLSX) on each report; if your plan caps export rows, export what it allows and add screenshots of the first page.

| Report | Path in SEMrush | Filename |
|---|---|---|
| Organic positions (keywords + ranking URLs) | SEO → Organic Research → **Positions** (set database; export all) | `semrush-organic-positions-<db>-YYYY-MM-DD.csv` |
| Ranking pages | Organic Research → **Pages** | `semrush-organic-pages-<db>-YYYY-MM-DD.csv` |
| Organic competitors | Organic Research → **Competitors** | `semrush-organic-competitors-<db>-YYYY-MM-DD.csv` |
| Backlinks | Backlink Analytics → **Backlinks** (all types; include follow/nofollow column) | `semrush-backlinks-YYYY-MM-DD.csv` |
| Referring domains | Backlink Analytics → **Referring Domains** | `semrush-referring-domains-YYYY-MM-DD.csv` |
| Anchors | Backlink Analytics → **Anchors** | `semrush-anchors-YYYY-MM-DD.csv` |
| Indexed / top linked pages | Backlink Analytics → **Indexed Pages** | `semrush-indexed-pages-YYYY-MM-DD.csv` |
| Backlink gap (optional) | Backlink Gap → add 2–4 real competitors | `semrush-backlink-gap-YYYY-MM-DD.csv` |
| Keyword gap (optional) | Keyword Gap → same competitors | `semrush-keyword-gap-<db>-YYYY-MM-DD.csv` |
