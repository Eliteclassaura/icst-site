# C5.5 remainder — security report

**Date:** 2026-09-10 · **Base:** `a1d0864` (tag `c8`) · **Decision:** ADR-030 · **Risks added:** R63–R66

C5.5 adds three things that carry real risk: files the Factory hands to other systems (bundles, packs, artboards), files other systems hand back (design-system exports), and text that steers a Claude session (skills). This report states the model, what is enforced where, what is tested, and what remains open.

## 1. Posture

**Refuse, do not repair.** Every check in this checkpoint rejects hostile input with a named rule rather than rewriting it. Sanitising by rewriting requires the checker and the browser to agree on where a tag ends, and they periodically do not; a design artefact has no reason to accept input that needs repairing in the first place. The cost is that a legitimate-but-odd input gets a clear error instead of silent repair, which is the right trade for artefacts that travel.

**A design artefact needs no capability.** It is a static picture of a design system: no script, no network, no embedding, no navigation. That makes an allow-list practical rather than aspirational — the entire legitimate surface is tags, attributes, `data:` images and relative font URLs.

**Trust boundaries are named.** Three of them: what we emit (bundle, pack, artboards), what we ingest (design exports), and what steers a session (skills). Each has its own gate, and none of them assumes another has already checked.

## 3. Deliberate allowances

Three things are permitted, each for a stated reason:

1. **Outbound `<a href>`.** A link is content — a cited source, a profile — and does not fetch. The first version of the policy refused the footer's profile link and the evidence block's four citations, which would have made the gate something people route around. Resource-loading attributes (`src`, `poster`, `xlink:href`, `<link href>`) remain refused.
2. **`style-src 'unsafe-inline'` in the card CSP.** A card is one document with its stylesheet inlined; there is nothing else it could be. `default-src 'none'` means no script can exist to exploit it.
3. **Vendored third-party skills ship scripts.** That is precisely why they are vendored and pinned by directory hash rather than trusted, and no first-party skill invokes them. `skills:verify` re-checks their pins with the same algorithm `install-skills.mjs` used to write them.
